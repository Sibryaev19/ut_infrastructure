# ut_infrastructure

Инфраструктура для universal_toolkit и работы с данными: имитация платформы
datalab, MCP-слой для агентов, библиотека инструментов для ноутбуков,
инфраструктурные сервисы и стенды. Собирается по кирпичикам — части
переиспользуются и вне datalab.

## Проекты

- **[local_datalab](local_datalab/)** — локальная имитация datalab на Docker:
  настоящий JupyterHub, который при логине спавнит персональный контейнер
  с notebook'ом и сервером (DockerSpawner), proxy-порты
  `/user/<имя>/proxy/<порт>/`, персистентность через маунты. Зачем: отрабатывать
  datalab_mcp без боевой платформы. Разворачивается двумя командами
  (`./setup_linux`, `./start_linux`) — вся конфигурация в `.env`.
- **[datalab_mcp](datalab_mcp/)** — MCP-инфраструктура для работы с datalab:
  `server/` — серверная часть (FastAPI: workspaces, transfer данных),
  живущая на платформе, `mcp_server/` — MCP-слой, через который LLM-агент
  умеет то же, что и человек в интерфейсе.
- **[universal_toolkit](universal_toolkit/)** — универсальная среда и библиотека
  модулей для ежедневной работы с данными в datalab: GP, HDFS, trino, spark,
  файлы. Идея — один импорт и готовые настроенные инструменты вместо «простыней»
  настроек в каждом ноутбуке: фасад `Toolkit()` отдаёт настроенные экземпляры,
  модули ленивы (тяжёлое грузится при первом использовании), а если что-то
  не так — ошибки-инструкции вместо стектрейсов. Двойное имя: в git —
  `universal_toolkit`, в datalab будет `oarb_toolkit`. Легаси-донор —
  в `source/`, правила оформления модулей — в `.for_agent/module-contract.md`.
- **[datalab_data_transfer](datalab_data_transfer/)** — тестовый стенд
  передачи данных: клиент-сервер для отработки transfer-сценариев до
  появления полноценного datalab_mcp.

## Как части связаны

- `local_datalab` имитирует платформу локально — на ней отрабатывается `datalab_mcp`.
- `datalab_mcp` — код платформы: `server/` живёт на datalab/имитации, `mcp_server/` — агентский слой.
- `universal_toolkit` — библиотека внутри пользовательских ноутбуков на платформе.
- `datalab_data_transfer` — отдельный стенд под transfer-сценарии.
