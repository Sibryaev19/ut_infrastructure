## Цель
Универсальная среда: удобно в Jupyter, в скриптах и в разработке; на Windows и
Linux; в контуре без интернета и снаружи. Главный критерий — клиентский путь,
а не формальности.

## Идея: среда → фасад → модули
- Модуль не знает, где работает: никаких `os.environ`, дефолтных хостов, `sys.path`.
- Импорт бесплатен: без соединений, env и тяжёлой инициализации.
- Вся среда (JupyterHub-пользователь, Kerberos, HDFS, Spark) — только в фасаде.
- Фасад ничего не реализует: композиция и ленивое создание.

Так «удобно в Jupyter» и «универсально» не конфликтуют.

## Слои
```
knowledge   skills, guides            ← знания, ничего не импортируют
surfaces    ноутбук, CLI, MCP, apps   ← способы пользоваться
facade      сборка среды              ← единственное место, знающее про окружение
modules     возможности               ← независимые, переносимые
core        конфиг, реестр, ошибки    ← без внешних зависимостей
```
Зависимости идут только вниз.

## Контракт модуля
- Шаблон: `__init__.py` (реэкспорт + `__all__` + `__version__` + `META`),
  `requirements.txt`, `src/`, тесты.
- `META`: `env` (portable | network | datalab), `os` (any | linux | windows),
  `deps`, `status` (draft | stable | legacy).
- `available() -> (bool, reason)`: можно ли здесь работать и почему нет.
- Всё внешнее — явные параметры конструктора.
- Переименование класса — с алиасом старого имени на один релиз.

## Клиентский путь
```python
from universal_toolkit import toolkit
t = toolkit()          # профиль определился сам, тяжёлого не создано
t.spark                # лениво
t.db.gp()              # сгруппированный доступ
t.files.read_excel(...)
t.available()          # что здесь работает
```
Правила: один импорт, ноль настройки; ленивость; ошибка = инструкция;
выход напрямую — `from universal_toolkit.modules... import ...`.

## Группы модулей (гипотеза, уточняется при пересмотре модулей)
`data_transfer`, `databases`, `distributed`, `spark_tools`, `file_tools`,
`dev_tools`, `datalab`. Группа — домен, среда — метаданные.

## Две машины
- `.gitattributes` → LF везде; ни одного абсолютного пути в коде.
- `META.os` честно разделяет платформенные и кроссплатформенные модули.
- `venv` на каждой машине свой, в git нет.
- **Тесты — в git** (предложение на согласовании).

## `old/` как донор
Переносим по одному модулю. Новый модуль рождается с паспортом и тестом.
Дубли удаляются после сверки. `old/` — не пакет и не на пути импорта.
