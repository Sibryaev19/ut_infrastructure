# Контракт модуля universal_toolkit — инструкция по созданию

**Назначение файла:** передать на вход (агенту или человеку) для создания нового
модуля по правилам проекта. Самодостаточен: не требует другого контекста.
Проверенный эталон механики — `develop/test/modules/dev_tools/dep_demo/`.

---

## 1. Структура (создавать ровно такую)

```
universal_toolkit/modules/<группа>/<имя_модуля>/
├── __init__.py        # ЛИЦО: контракт, его читают фасад, реестр, доктор, люди
├── src/
│   ├── __init__.py    # пустой — делает src пакетом для relative-импорта
│   ├── config.py      # системные константы среды (для специализированных
│   │                  # модулей; portable-модулю не нужен)
│   └── <имя>.py       # ПОТРОХА: реализация
├── tests/
│   ├── unit/          # юнит-тесты: гоняются ГДЕ УГОДНО, контракт и логика
│   │   └── test_<имя>.py
│   └── smoke/         # ТОЛЬКО для модулей, привязанных к живой среде (datalab);
│       └── test_live.py   #  проверяют «дышит ли»: соединение + простейший запрос
└── requirements.txt   # МАНИФЕСТ установки: для pip и доктора
```

- `<группа>` — домен (`databases`, `data_transfer`, `distributed`,
  `spark_tools`, `file_tools`, `system` и т.п.). Папок «по популярности»
  (`special/`, `popular/`) НЕ заводить: группа — про содержание.
- portable-модулю (без привязки к среде) папка `smoke/` не нужна.
- Файлы тестов: `test_*.py`; функции: `test_*`; проверки — обычные `assert`.

## 2. `__init__.py` — лицо модуля

Шаблон:

```python
from importlib.util import find_spec

from .src.<имя> import <ОсновнойКласс>

__all__ = ["<ОсновнойКласс>", "available"]   # всё публичное; внутренности НЕ вносить
__version__ = "0.1.0"                        # semver: ломаю API -> старшая цифра

META = {
    "env": "portable",      # portable | network | datalab
    "os": "any",            # any | linux | windows
    "deps": ["requests"],   # внешние зависимости, список == requirements.txt
    "status": "draft",      # draft | stable | legacy
}


def available() -> tuple[bool, str]:
    """Можно ли работать здесь? Проверяет dep БЕЗ их импорта (find_spec)."""
    missing = [d for d in META["deps"] if find_spec(d) is None]
    if missing:
        return False, "нет зависимостей: " + ", ".join(missing)
    return True, "все зависимости на месте"
```

Назначение каждой детали:

| Деталь | Механика | Кто читает |
|---|---|---|
| реэкспорт `from .src... import X` | относительный импорт поднимает имя наверх; потроха можно переставлять | пользователь, фасад |
| `__all__` | влияет только на `import *`; остальное — декларация границы. Ничего не прячет! | IDE, линтеры, фасад |
| `__version__` | просто атрибут-договорённость (semver) | люди, обновления |
| `META` | обычный словарь; читается без импорта тяжёлого | реестр, фасад, доктор |
| `available()` | обычная функция; `find_spec` вместо импорта | доктор в гейте геттера |

Обязательное правило: **на верхнем уровне `__init__.py` и `src/*.py` — только
определения.** Никаких соединений, чтения env, создания файлов и настройки
логгеров: `__init__.py` исполняется при первом `import` (потом кэшируется в
`sys.modules`) — побочки недопустимы.

## 3. `src/` — реализация

Шаблон класса:

```python
class <ОсновнойКласс>:
    def __init__(self, почти_константа=None):
        # конструктор НЕ трогает зависимости и соединения
        self._почти_константа = почти_константа  # None -> дефолт разворачивается внутри

    def do_work(self, входные_параметры):
        import requests  # ЛЕНИВО: зависимость грузится ВНУТРИ метода
        ...
```

Правила:

- **Публичных имён может быть несколько** (классы/функции одного домена:
  `DistTask` + `Podnet`, `GPConnector` + `GPTool`). Границу задаёт `__all__`.
  Внутренние механизмы (`Queue`, `myLogger`) живут в `src/` и в `__all__`
  не попадают — «прятать» их не нужно, это просто не обещанные имена.
- **Зависимости — ленивые импорты внутри методов.** Тогда модуль импортируется
  даже там, где dep не установлен, а тяжёлое грузится только при реальном
  использовании.
- **Параметры — три группы:**
  1. *фиксированные* (системные константы: хосты, kerberos, spark-сессия) —
     хардкод в модуле, это его природа, а не окружение;
  2. *входные* — всегда явные, дефолтов нет;
  3. *почти-константы* (меняются редко) — дефолт в модуле через `None`,
     разворачивается внутри. Portable-модуль почти-констант не имеет.
  Секреты — не сюда: только извне, никогда не логируются.
  Сессионное (кто я сейчас) — НЕ читается модулем из env; приходит параметром
  (его знает агрегатор).
- **Ошибка = инструкция**: при недоступной зависимости/среде поднимать
  человекочитаемое сообщение «что не так + как починить» (на русском),
  а не стектрейс.
- **Правило удобства**: ВХОД — ноль настроек (агрегатор отдаёт готовый
  объект); в РАБОТЕ параметрами должно быть только содержание пользователя.
  Сложный функционал не обязан укладываться в «3 строки» — но простыня
  настроек перед работой недопустима.
- **Системные константы — в `src/config.py`** (решено 2026-11-27; для
  специализированных под среду модулей): одна точка правды для хардкодов
  (пути, хосты, kerberos-флаги). Правила:
  - в коде — только `from . import config` и обращения `config.X` —
    никогда `from .config import X` (копия значения не подменяется);
  - тесты подменяют значения атрибутами (`monkeypatch.setattr(config, "X", ...)`)
    — файл не трогается;
  - всё, что строится из констант (filesystem, соединения), создаётся ЛЕНИВО
    при первом обращении, не на импорте config.py.
- Модуль не трогает `sys.path` и не вычисляет пути к самому себе.
- Переименование класса — с алиасом старого имени на один релиз.

## 4. `requirements.txt`

Внешние зависимости, по одной в строке. **Источник правды — requirements.txt**
(решено 2026-11-26); `META["deps"]` — зеркало для `available()`, держать
синхронно. Расхождение считать ошибкой оформления.

## 5. Тесты

**`tests/unit/`** — контракт и логика, без живой среды. Обязательные проверки
нового модуля:

```python
import sys


def test_import_no_side_effects():
    """Импорт без побочек: тяжёлые dep не поднялись."""
    import <пакет>
    for dep in <пакет>.META["deps"]:
        assert dep not in sys.modules


def test_available_is_honest():
    ok, reason = <пакет>.available()
    assert isinstance(ok, bool) and isinstance(reason, str)


def test_none_default_unwraps():
    """Почти-константа: None -> дефолт модуля."""
    ...


def test_error_is_instruction():
    """Ошибка содержит способ починки, не сырой стектрейс."""
    ...
```

Плюс тесты логики модуля (чистые части: маппинги, преобразования).

**`tests/smoke/`** — только для модулей с живой средой. Минимум: соединение
поднялось, простейший запрос ответил. Гоняются ТОЛЬКО в подходящей среде
(в контуре); упавший smoke — обычно «окружение», а не «код».

Запуск (из папки модуля):

```bash
pytest tests/unit     # на любой машине, каждый день
pytest tests/smoke   # в подходящей среде, после переноса
pytest tests/unit -v # подробно
pytest tests/unit -x # стоп на первом провале
```

## 6. Чек-лист создания нового модуля

1. Определить группу (домен) и имя.
2. Создать дерево из раздела 1 (без `smoke/`, если модуль portable).
3. Заполнить `META` честно (`env`, `os`, `deps`, `status=draft`).
4. Написать `available()` (шаблон раздела 2).
5. Реализовать класс: ленивые dep, три группы параметров, ошибки-инструкции.
6. Заполнить `requirements.txt`, сверить с `META["deps"]`.
7. Написать `tests/unit/` (4 обязательных проверки из раздела 5 + логика).
8. Прогнать `pytest tests/unit` — все зелёные.
9. Если среда живая — набросать `tests/smoke/` для прогона в контуре.
10. Геттер в фасад добавляется отдельно (фасад — не часть этого файла).
