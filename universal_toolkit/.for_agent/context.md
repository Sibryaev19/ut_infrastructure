# context — universal_toolkit

## Что это
`universal_toolkit` — универсальная среда и библиотека модулей. Разрабатывается
здесь (ноут Windows + домашний Linux), переносится в контур компании (Linux datalab,
без интернета). Репозиторий живёт внутри `funny_projects` — сознательный выбор
пользователя, переезд в отдельный репозиторий не планируется.

Роли:
- **`universal_toolkit`** — новое решение, проектируется с нуля.
- **`oarb_toolkit/`** — легаси-дамп кода (37 файлов), источник для новых модулей;
  уйдёт в `old/`.
- **`UTool.py`** — легаси-вход, живёт в `/home/datalab/nfs/UTool.py`, ноутбуки
  находят его через `sys.path.append("/home/datalab/nfs")`. Разбирается на модули,
  его API — привычка пользователя, которую сохраняем шимом.

Исходное описание проекта — `../контекст.md`.

## Глобальные требования (шаг 1)
Проект большой, в одном чате не делается. Репозиторий развивается постоянно.

1. **Две машины, три площадки**: ноут (Windows), домашний Linux-комп (там же
   имитация datalab), контур компании. Код живёт в **git** — единственный источник.
2. **Код не только для datalab**: модули под разные задачи и разные ОС.
3. **`old/`** — архив-донор. Текущее содержимое (включая `folder_to_txt.py`)
   уходит туда; новая архитектура строится рядом, опираясь на old.
4. **Главное — удобство пользователя.** Опора на клиентский путь, не на
   формальности и документацию.
5. Каждый модуль пересматривается заново: улучшить / объединить / разделить.
6. **Тестируем всё.** При необходимости на Linux-компе ставится HDFS, Greenplum.
7. Репозиторий — не только модули, а **полноценная среда** (skills, mcp, apps, guides).

## Площадки
| | Ноут | Домашний Linux | Контур |
|---|---|---|---|
| ОС | Windows | Linux | Linux, datalab |
| Сеть | есть | есть | нет |
| Python | 3.11 | 3.12 | 3.12 (целевой) |
| GP/Kerberos | нет | можно поднять | есть |
| Jupyter | нет | можно поднять | есть |

Следствия: модули не привязаны к ОС; datalab-модули локально проверяются на фейках;
код переносим файлами, без абсолютных путей.

## Легаси-аудит (факты о коде в `oarb_toolkit/`)
- `UTool.py` — 700 строк, v3.1: spark-сессия, файлы, excel, pickle, HDFS, CSS
  ноутбука в одном классе.
- Побочки на импорте: `JUPYTERHUB_USER` без fallback, два HDFS-подключения
  с Kerberos, `display(HTML(...))`, тяжёлые импорты (pyspark, psycopg, dill).
- `UTool.get_gp_connector()` берёт `utool_dir.gp_connector`, а не новый модуль.
- `from utool_dir.distributed_task import ...`, хотя пакет лежит в корне
  `distributed_task/` — импорт не соответствует дереву.
- f-string на строке 205 вложенными кавычками — валиден только на 3.12 (не баг).
- `get_view_list()` объявлен без `self`.
- Дубли: `utool_dir/data_caster.py`, `gp_connector.py`, `zip_converter.py`.
- Нет `modules/__init__.py`; в requirements опечатка `request` вместо `requests`.
- В `utool_dir/` 7 скриптов, включая `trino_connector.py` (не упомянут в контексте).
