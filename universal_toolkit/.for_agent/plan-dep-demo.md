# plan — эксперимент dep_demo

Статус: **done** · 2026-11-26 · шаг 3 завершён
Задача — учебная: прочувствовать работу модулей с зависимостями
на игрушечном примере, до переноса реальных модулей.

## Где лежит
`develop/test/`:
- `modules/dev_tools/dep_demo/` — модуль-контракт
  (`__init__.py` с `META`/`available()`/`deps_info()`, `src/dep_demo.py`,
  `requirements.txt`)
- `toolkit_mini.py` — мини реестр+фасад (скан папок, отчёт, ленивое
  `t.dev_tools.dep_demo`, кэш)
- `run_checks.py` — 9 сценариев на экран

## Результаты (прогон 2026-11-26, Windows, Python 3.11)
- Импорт модуля работает при отсутствии dep ✅ (ленивые импорты внутри методов).
- `available()` честно: `False, 'нет зависимостей: nonexistent_xyz'`.
- Ленивость доказана через `sys.modules`: polars/requests грузятся только
  при первом вызове метода.
- Ошибка отсутствующего dep = инструкция `pip install ...`, без стектрейса.
- Фасад: один импорт, ноль настройки, объекты кэшируются.

## Нюанс окружения
Консоль Windows в cp1251: для прогонов нужен `PYTHONIOENCODING=utf-8`
(и без `-I`, который игнорирует env). Это локальный нюанс запуска,
не проблема кода.

## Вывод для правил модулей
Приёмы dep_demo — кандидаты в контракт реального пакета:
ленивый импорт dep внутри метода, `available()` через `find_spec`
без импорта, ошибка-инструкция, реестр по папкам, фасад-кэш.
