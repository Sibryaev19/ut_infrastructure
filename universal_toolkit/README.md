# universal_toolkit

Универсальная среда и библиотека модулей для ежедневной работы с данными:
GP (Greenplum), HDFS, trino, hive, spark, файлы, LLM и модели.

> Двойное имя: в git проект называется `universal_toolkit`,
> в datalab — `oarb_toolkit`. Это один и тот же инструментарий.

## Зачем

Работа — datalab и Jupyter-ноутбуки. Цель — чтобы рутинные операции делались
за минуты и без «простыней настроек»: один импорт — и готовые настроенные
инструменты. Никаких соединений и чтения окружения на этапе импорта: тяжёлое
грузится лениво, в момент первого использования.

## Как это будет выглядеть

```python
from universal_toolkit import Toolkit

t = Toolkit()
gp = t.get_gpconnector()      # настроенный коннектор: параметры можно передать
gp.sql("select ...")          # -> готовый DataFrame

# или напрямую, без фасада:
from universal_toolkit import GPConnector
```

Планируемый фасад — класс `Toolkit()` (аналог старого `UTool`):
типизированные геттеры настроенных экземпляров, отчёт
`t.available()` — «что здесь работает и почему нет».

## Структура репозитория

```
universal_toolkit/        # репозиторий, он же будущий пакет
├── modules/              # группы модулей по доменам (databases, data_transfer, ...)
├── guides/               # примеры и инструкции, в т.ч. для агентов-подсказчиков
├── source/oarb_toolkit/  # ВРЕМЕННО: легаси-донор, удаляется по завершении
├── develop/              # песочница экспериментов (в git не входит)
└── .for_agent/           # память проекта для AI-агентов (INDEX.md — вход)
```

Репозиторий и есть пакет: `__init__.py` в корне, весь репо импортируется
целиком (`from universal_toolkit import Toolkit`).

## Модули

Модуль — самодостаточная единица: `__init__.py` (паспорт `META`, `available()`,
реэкспорт), `src/` (реализация, ленивые зависимости), `tests/unit` +
`tests/smoke`, `requirements.txt`. Правила создания — в
`.for_agent/module-contract.md`.

Принципы: импорт без побочек; системные константы — в модуле; сессионное
(кто я) — параметром снаружи; ошибка = инструкция, а не стектрейс.

## Разработка

Две машины (Windows-ноут и Linux-комп), git — единственный источник.
Требования: кроссплатформенность, ни одного абсолютного пути, LF
(`.gitattributes`), тесты — в git (юнит везде, smoke — только в подходящей
среде). Python 3.10+, целевой — 3.12.

Статус: архитектура согласована, идёт перенос модулей из легаси по одному.
Текущее состояние и задачи — в `.for_agent/INDEX.md`.
