## Задача 1 (главная): ✕ у ещё не начавшихся фаз
Идея пользователя: крестик отмены должен быть не только у идущей фазы,
но и у фаз в статусе «ожидание» — отказ от фазы до её старта.
- Фронтенд (`src/web/static/index.html`, renderBars): сейчас ✕ рисуется
  только при `job.status==='running' && data.status==='running' &&
  skippable.includes(p)`. Добавить ветку для `data.status==='pending'`.
  Текст confirm различать: для pending — «фаза не будет скачиваться»,
  для running — текущие предупреждения (частичная история / комментарии
  не сохранятся). Показывать ✕ только у фаз из плана запроса (phasePlan);
  «догрузка историй» (doload) — автоматическая, ✕ у неё не давать (как
  решено в v1: skippable = changelog|comments).
- Бэкенд уже готов: `request_skip` кладёт фазу в `job.skip_phases` без
  привязки к статусу фазы, воркер проверяет `cancelled(phase)` на первой
  же границе цикла → фаза сразу помечается `status="cancelled"` и
  пропускается; коммит/summary уже учитывают отмену (comments_saved=False,
  частичный changelog коммитится). Проверить только, что при отмене
  pending до старта фазы прогресс-колбэк всё же выставит ей
  `status="cancelled"` (сейчас это происходит в ветке отмены внутри
  цикла — должно сработать на первом чанке; убедиться тестом).
- Нюанс: если пользователь отменил фазу pending по ошибке — кнопки
  «вернуть» нет (как и в v1). Осознанное решение, не баг.
- Проверка: `python -m pytest` (61), живой прогон CURATOR/apache —
  ✕ на «ожидание» сразу после старта, убедиться что фаза стала
  «отменена» до начала скачивания, summary честный.
