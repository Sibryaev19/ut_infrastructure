# INDEX — local_datalab

Локальный стенд: полноценный jupyterhub в Docker, имитирующий datalab —
для тестирования `datalab_mcp` (server/ + mcp_server/) без реального datalab.

## Текущее состояние (2026-11-28)
- Стенд проверен пользователем (2026-11-25): логин, спавн, терминал,
  hello-world сервер — «работает всё». e2e mcp_server против стенда
  пройден 2026-11-25 (см. ../datalab_mcp/.for_agent/INDEX.md).
- ДАЛЬШЕ (обсуждено 2026-11-28, не начато): пользователь создаёт СОСЕДНИЕ
  модули greenplum/ и hdfs/ в ut_infrastructure (не здесь); со стороны
  стенда правок не требуется — будущая связка через external docker-сеть
  ${NETWORK_NAME}. Кратко — в context.md, полные решения — в корневом
  .for_agent/context.md.
- БУДУЩЕЕ (названо пользователем, не начато): stop-скрипт, idle_culler
  (автогашение контейнера), форма выбора образа/настроек контейнера после
  логина (spawner options form), кастомное оформление, TLS на стенде
  (отложено «как-нибудь потом»; интересен и как учебный мини-CA для
  VERIFY_TLS=true) — отдельными папками рядом с platform/.
- Хвосты: `sudo rmdir /workspace` (мусор в корне хоста);
  workspace/test_app.py — тестовый, решить судьбу.
- ХОСТ: домашний комп с Ubuntu, Docker 29.1.3 + Compose v2.40.3 проверены.
  Всё на одной машине: стенд и mcp_server, адрес `http://localhost:8000`.
- Границы: этот проект — только имитация datalab; datalab_mcp и
  инфраструктурные модули (gp/hdfs) — соседние проекты.
